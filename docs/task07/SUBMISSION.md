# 과제 7 제출 정리

플랜두씨 다이어리에 이메일 가입·로그인과 계정별 자료 접근 제한을 붙였습니다. 아래는 확인한 구현과 2026년 10월 20~24일의 관찰 결과입니다. 계정 삭제와 전용 5일 집계 화면은 아직 없으므로 카드 5 전체 완료로 제출할 상태는 아닙니다.

## ① 무엇으로 붙였나

인증 라이브러리 Better Auth 1.7.11과 @better-auth/drizzle-adapter 1.7.11을 사용합니다. 비밀번호는 라이브러리의 scrypt로 해싱하고, 로그인 상태는 D1 데이터베이스 세션으로 확인합니다. 세션은 발급·갱신 뒤 7일 동안 유효하며 하루가 지나 사용하면 갱신합니다. 로그아웃하면 서버 세션을 폐기합니다.

## ② 왜 그걸 골랐나

기존 D1·Drizzle 자료를 유지하면서 비밀번호 해싱과 쿠키 처리를 라이브러리에 맡길 수 있어서 선택했습니다. 직접 구현은 비밀번호와 세션 보안에 대한 책임 범위가 커 제외했습니다. Sites의 ChatGPT 인증도 검토했지만 앱 내부 이메일 가입과 오류 응답을 직접 검증하는 이번 과제에는 Better Auth를 선택했습니다.

## ③ 어디를 어떻게 고쳤나

가입은 app/auth-form.tsx에서 입력을 받아 worker/index.ts의 인증 경로를 거쳐 lib/auth.ts의 Better Auth로 전달됩니다. 계정과 해시가 db/schema.ts의 인증 표에 저장됩니다. 로그인도 같은 경로를 거쳐 서버 세션과 HttpOnly·Secure·SameSite=Lax 쿠키를 발급합니다.

로그아웃은 app/account-bar.tsx에서 인증 sign-out 경로를 호출해 서버 세션을 폐기하고 로그인 화면으로 이동합니다. 자료 조회는 worker/index.ts에서 세션을 확인한 다음 lib/access.ts에서 계획·할 일의 소유자를 검사합니다. app/api/entries/route.ts와 review·export 경로도 현재 사용자로 조회 범위를 제한합니다. 화면에서 숨기는 것뿐 아니라 서버 조회·변경 전에 검사합니다.

실행 기록 수정은 app/execution-log.tsx와 app/api/executions/route.ts에 있습니다. 원래 예상 시간을 바꾸지 않고 실행 시각·소요 시간·막힌 이유를 고칩니다. 미실행은 사용자가 확인한 경우에만 0분으로 남깁니다.

## ④ 안 열리는 것을 확인한 기록

아래는 기존 운영 검증 파일에 남은 결과이며, 비밀번호와 쿠키는 가려 보관했습니다. 상세 요청 본문과 실제 검증 ID는 연결한 JSON에 있습니다.

| 확인 | 정상 요청·응답 | 거절 요청·응답 | 증거 |
| --- | --- | --- | --- |
| 비로그인 자료 조회·내보내기 | 로그인 후 GET /api/entries, /api/export → 200 | 쿠키 없이 같은 API → 401, 로그인이 필요합니다 | CARD1.md, card4-ownership.json |
| A에서 B 자료 읽기 | 본인 계획 목록 GET → 200 | 상대 계획 이력 GET /api/entries?history=상대ID → 404 | card4-ownership.json |
| A에서 B 자료 수정·삭제 | 검증 자료를 본인 계정으로 생성·조회 → 200 | 상대 계획·할 일 POST 및 DELETE → 404 | card4-ownership.json |
| 반대 방향·목록 분리 | B의 목록 → 200, B 자료만 포함 | B에서 A 읽기·수정·삭제 → 404; URL·헤더·본문 소유자 위조에도 본인 목록만 반환 | card4-ownership.json |
| 로그아웃 후 이전 값 재사용 | 같은 쿠키로 GET /api/entries → 200 | 로그아웃 뒤 동일 쿠키·주소·방식 → 401 | card3-session.json |

수정·삭제 거절 앞뒤로 상대 계정의 6개 자료 표 내용과 건수를 비교했고 변경과 새 자료가 없었습니다. 정상 생성과 거절된 수정·삭제는 별도 시험입니다. 각 변경 메서드의 정상 성공 응답과 거절 응답을 일대일로 나란히 보여 주는 최종 증거 묶음은 추가 정리가 필요합니다. 실제 7일 경과나 비밀번호 변경 뒤 세션 폐기는 시험하지 않았습니다.

## ⑤ AI와 나

- AI에게 맡긴 일: 인증·소유권 검사와 실행 기록 수정 구현, 검증 요청 작성, 실제 기록의 계산과 제출문 정리.
- 내가 직접 판단한 일: 관찰 질문·60분 예상·시간 초과분 지표를 정하고, 아침에 시작하는 규칙을 선택했으며 실제 수행 여부와 막힌 이유를 확인했다.
- AI 제안을 따르지 않은 일: 명시적으로 거절한 제안은 없었다. 제안된 처리 규칙을 검토해 채택했고, 실제 날짜가 틀리거나 하지 않은 일이 섞였을 때 내 사실에 맞게 바로잡았다.

## ⑥ 아직 못 막은 것

비밀번호 재설정과 두 번째 인증 수단은 구현하지 않았습니다. 비밀번호를 잊으면 앱에서 복구할 수 없고, 비밀번호가 유출되면 추가 인증으로 막을 수 없습니다. 비밀번호 변경 후 기존 세션 폐기 시험도 하지 않았습니다. 계정 삭제 기능·삭제 안내와 5일 전용 자동 집계 화면은 아직 없습니다. 호스팅 내부 파일까지 비밀값이 없다고 검증한 것은 아닙니다. 과제 6 당시 공개했던 자료는 과거 Git 기록에 남아 있을 수 있어 현재 로그인만으로 과거 공개본까지 회수되지는 않습니다.

## 5일 관찰 결과

질문은 ‘Velog 포스팅에서 예상보다 오래 걸리는 시간을 줄일 수 있을까?’입니다. 지표는 시간 초과분, 단위는 분이며 실제 시간에서 예상 시간을 뺍니다. 하루 예상은 60분으로 유지했습니다. 미실행 확인은 0분, 알 수 없는 누락은 미기록으로 처리합니다. 같은 날짜·활동의 중복은 하나로 정리하고 이상값도 이유와 함께 유지합니다. 계산 중 반올림하지 않고 최종 합계·평균만 소수 첫째 자리로 표시하며 주 시작은 월요일입니다.

| 서울 날짜 | 일차 | 예상(분) | 실제(분) | 초과분(분) | 내용 |
| --- | --- | ---: | ---: | ---: | --- |
| 2026-10-20 | 1 | 60 | 30 | -30 | 4-1 이론 복습, 피곤해서 중단 |
| 2026-10-21 | 2 | 60 | 30 | -30 | 4-1 추가 복습, 4-2 미실행 |
| 2026-10-22 | 3 | 60 | 0 | -60 | 캡스톤 디자인을 3시간 넘게 해 4-2·4-3 미실행 |
| 2026-10-23 | 4 | 60 | 0 | -60 | AI 역량검사 준비로 미실행 |
| 2026-10-24 | 5 | 60 | 0 | -60 | AI 역량검사 준비로 미실행 |

합계는 예상 300분, 실제 60분, 초과분 -240분이며 하루 평균 초과분은 -48.0분입니다. 같은 날 여러 할 일의 미실행을 서로 다른 관찰 날짜로 세지 않았습니다. 4·5일차 결과는 10월 26일에 사용자 확인을 받아 소급 입력했으며 당시 작성한 것처럼 표현하지 않습니다.

2일차 뒤 3일차 시작 전에 ‘피곤한 밤 대신 아침에 작업 시작하기’로 규칙 하나를 바꿨습니다. 확인 시각은 2026-10-22 09:27:05+09:00, 계획 이력 저장 시각은 09:27:45.340+09:00입니다. 피곤해서 중단하고 예정 포스팅이 밀린 점이 이유입니다. 참조 실행 ID는 1일차 8e53feb1-e1cc-4962-963d-5499b7faac46, 2일차 18d03d4c-65ed-4950-aa64-4af5b97fbe45입니다.

변경 전 2일의 초과분 합계는 -60분·평균 -30.0분, 변경 후 3일은 -180분·평균 -60.0분입니다. 지표가 작아졌지만 사흘 미실행한 결과이므로 효율 개선으로 해석하지 않습니다. 다음 계획은 ‘중요 일정이 있는 날은 포스팅 대신 소제목 3개와 핵심 내용만 정리하기’입니다. 계산은 계획의 돌아보기 본문에 저장했으며 기존 할 일 마감일 기준 자동 집계와는 구분합니다.
